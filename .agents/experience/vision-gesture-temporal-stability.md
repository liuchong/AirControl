# 摄像头手势时序稳定性经验

- 不要把全部手部关键点组成“全有或全无”的帧。每个手势应声明自己依赖的点，无关点缺失只影响依赖它的分类器；真正没有任何可靠手部信号时才启动丢手安全计时。
- 光标平滑必须使用相邻帧的真实时间间隔。固定的“每帧移动百分比”会让高帧率更快、低帧率更慢；时间感知指数响应才能让不同摄像头帧率收敛到同一手感。
- 点击手势需要把“识别位置”和“手指收拢过程”分开。第一帧候选就保存屏幕锚点并抑制普通移动，确认点击后仍在锚点投递按下与释放，才能避免捏合动作本身把光标带走。
- 摄像头遮挡是短暂且局部的。闭合、张开都应有连续样本确认，局部证据缺失可给一个短宽限；整手丢失仍走更长的安全释放时限。两种超时不能混为一谈。
- 跨语言集成样例至少要带时间戳、关键点置信度、候选阶段坐标变化和输出坐标断言，不能只统计点击命令数量，否则会漏掉帧率依赖、点击漂移和平台边界语义变化。
- 连续识别失败不等同于摄像头已经失效，也不等同于用户主动停止。应把“用户仍想控制”“视觉处理暂时挂起”“捕获会话不可恢复错误”分成三个状态：暂时挂起保持摄像头并用连续成功帧自动恢复；真正的会话错误才停止捕获；下一次用户开始必须重新配置设备。
- 核心 `stop` 不只是释放按键，还必须清除会话级暂停和辅助锁存。否则平台界面即使显示重新开始，共享核心仍可能留在旧暂停状态，形成无法通过停止/开始恢复的假死。
- 双手辅助的生理手别是安全输入，不是装饰元数据。未知手可回退普通单手控制，但绝不能获得左手暂停、拖拽或点击修饰权限；这一边界需要 Rust 行为测试与跨语言非法枚举测试共同覆盖。
- 表示“抓、放、挥”等动作时，不要把单帧姿势直接等同于用户意图。应显式建模“稳定起始姿势 → 有方向的过渡 → 连续终止姿势”，并给过渡设置截止时间、反向取消和完成后的中性等待；这样单独出现的拳头既不会误触，也不会在释放后立即重复触发。
- 过程手势开始后应冻结它要作用的目标锚点，并暂时屏蔽同一只手的普通手势分类。否则收拢手指本身会移动光标、点击或滚动，最终操作的对象会偏离用户开始动作时选择的对象。
- 跨平台过程手势应在共享核心输出“开始、连续更新、结束”抽象命令，平台层只解析操作系统对象并执行。输出容量不足的重试、停止和丢信号释放都要覆盖开始/结束命令，不能只对鼠标按键做事务保护。
