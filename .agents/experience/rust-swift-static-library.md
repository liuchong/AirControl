# Rust 静态库接入 Swift 的可复用经验

- Swift 编译依赖的是静态库二进制，Xcode 不能从 Rust 源文件变化自动推导依赖；Rust 构建阶段应明确每次运行，否则可能链接到旧符号而误判源码问题。
- C 兼容接口只传定长数值结构、不透明句柄和调用方提供的输出缓冲区；所有入口捕获 Rust panic，并用状态码返回错误，避免跨语言展开异常或暴露 Rust 内存所有权。
- 默认设置、校验、手势位含义和 ABI 版本应由 Rust 与公共头文件共同定义；Swift 只负责持久化和转换，不重写业务判断。
- Swift 集成测试应链接真实 Rust 静态库并穿过 C 兼容接口。只测 Swift mock 会遗漏头文件、布局、符号和缓冲区容量问题。
- 会改变核心状态的 C 接口必须先在可复制的候选状态上计算输出，确认调用方缓冲区足够后再提交；否则调用方按“先询问容量、再重试”的常见模式会永久丢失一次性点击或按键释放。
- 跨语言共用的阈值必须由共享核心判定。平台外壳应传原始值与置信度，避免默认值变更后平台层仍保留旧常量。
- XcodeGen 管理的 `Info.plist` 和 entitlement 是生成产物，权限键必须写入 `project.yml` 的 `properties`。验证流程要先重新生成工程、再检查生成文件，否则直接修改 plist 会产生一次构建可用、下次生成失效的假通过。
