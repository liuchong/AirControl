# AirControl 架构记录

AirControl 使用单向链路：`AVCaptureSession` 摄像头帧 → Vision 手部与可选眼部关键点 → C 兼容接口 → Rust 手势/视线状态机 → 抽象鼠标/窗口命令 → 经权限门禁的 Core Graphics 鼠标投递器或 macOS 辅助功能窗口移动器。

Rust crate 是平台无关业务规则的唯一实现，负责关键点校验、手势时序、坐标映射、平滑、校准、设置校验和安全释放。Swift 只负责 macOS 摄像头、Vision 转换、设备标识持久化、权限、命令投递和界面，不得复制 Rust 判断。

普通摄像头视线辅助复用同一边界：Swift 只把 Vision 双眼轮廓和瞳孔转换成眼框内归一化样本；Rust `gaze.rs` 负责九点稳定采样、二维仿射模型、覆盖校验、显示器映射、真实时间平滑和低置信度/闭眼冻结。视线只在无手时粗定位；每次视线位置通过共享引擎重建外部光标锚点，右手首次出现不跳动，后续以 45% 相对增益精调。模型持久化只含数值系数，不含图像或身份信息。

C 兼容接口当前为 ABI 第 4 版。每个关节携带左、右或未知手别，Swift 将最多两手的 Vision 结果扁平化，Rust 重组为 `HandsFrame`。普通控制优先右手并允许未知手回退，左手辅助和过程性抓窗分别只接受明确左手、明确右手。引擎处理和停止使用“候选状态 → 容量检查 → 提交状态”的事务顺序；输出缓冲区不足时只报告所需容量，绝不消耗点击、抓窗开始或释放命令。点击使用带次数的显式命令，平台可投递真正的系统双击。校准器在创建时接收 Rust 设置中的最低置信度，Swift 只传递原始食指点和置信度。

已知关节的单个坐标或置信度无效时，Rust C 兼容接口将该测量视为缺失。Rust 为每种手势单独读取所需关节点：无关点缺失不打断当前手势，全部可靠点丢失才进入 0.20 秒丢手计时和安全释放；未知关节类型、空指针、非有限时间戳与非法缓冲区仍是调用错误。四指伸展/折叠由 `MCP → PIP → Tip` 的方向夹角与相对长度决定，不依赖画面纵轴，跨平台外壳不得复制这套判断。

光标滤波使用真实帧间隔和手部位移自适应计算，避免把固定“每帧比例”误当成时间常量。主/次捏合由 Rust `PinchTracker` 统一管理双样本闭合、双样本张开、0.08 秒局部丢点宽限和屏幕锚点；主捏合进入拖拽前禁止移动，长捏只在锚点按下，进入拖拽后才恢复移动。

双手辅助由 Rust `AssistTracker` 统一管理：姿势需稳定 0.12 秒且至少两个样本，左手遮挡宽限为 0.20 秒。张掌使用右掌相对位移和 40% 增益，单食指锁定，竖拇指把主短捏改为双击，V 手势滚动，三指拖拽，左拳暂停。右拳和未知手不得暂停或启用左手辅助。

过程性抓窗由 Rust `WindowGrabTracker` 统一管理：明确右手稳定张掌 0.12 秒后武装，必须在 0.65 秒内经过手指数下降并连续两帧握拳才能开始；孤立拳头无效。屏幕目标在张掌武装时冻结，掌心移动基准在握拳确认时重新落定，避免把收拢动作变成窗口首帧跳动。候选和抓住期间抑制普通手势，后续掌心相对位移输出平台无关的绝对屏幕坐标，重新张掌、丢手、左手辅助、停止或错误输出结束。macOS `SystemWindowController` 只负责用辅助功能接口定位光标下窗口、保存初始偏移并设置窗口位置；不可移动窗口软失败，不读取窗口内容。

安全边界位于两层：应用协调器只在用户已开启控制且辅助功能权限有效时处理命令；系统投递器再次检查辅助功能信任。所有停止和错误路径汇合到 `safeStop()`，先让 Rust 生成必要释放命令，再由系统投递器兜底释放本地记录的按键。

Vision 单帧处理错误仍向 Rust 转交一个空手帧，保证丢手计时和拖拽释放继续推进；连续 5 帧错误时只暂停命令投递并进入恢复状态，不停止摄像头，连续两个成功帧后自动恢复。真正的摄像头错误会停止会话；下一次开启必须重新配置当前摄像头。`Engine.stop()` 会释放按键并清除暂停，确保停止后重新开启不是死状态。摄像头与显示器 ID 独立存入 `UserDefaults`，启动时只恢复仍存在的设备，否则保存有效回退选择。

不可恢复的处理错误仍汇合到 `safeStop()`，`RunState.error` 保存具体错误文字并由主窗口直接展示，避免只有泛化状态而无法现场诊断。

九点校准的 macOS 协调层使用一次性恢复意图：开始前记录 `controlEnabled`，再安全停止；只有校准成功且摄像头、辅助功能权限仍有效时才复用统一摄像头重连入口恢复。取消、失败、权限变化和任何额外安全停止都会消费或清空意图，避免把旧会话状态带入下一次校准。

屏幕辅助光源完全属于 macOS 外壳：`FillLightSettings` 独立存入 `UserDefaults`，`FillLightOverlayController` 在目标显示器绘制忽略鼠标且不成为键盘窗口的边缘柔光。它不读取屏幕、不申请权限、不进入 Rust；未来平台如需同类能力应分别使用各自窗口系统实现。

测试以抽象 `CursorControlling` 记录命令，不在自动测试中移动真实光标或真实窗口。Cargo 测试覆盖业务核心与 FFI，Swift `integration_test` 通过真实静态库验证跨语言链路，窗口控制单元测试验证包含负坐标的位移计算。摄像头和系统授权只在应用目标使用，核心测试不需要硬件权限；真实窗口策略由手动验收补充。

`project.yml` 是 Xcode 工程、`Info.plist` 和 entitlement 的生成源。摄像头用途说明与摄像头权限必须写在这里；统一验证会在每次 `xcodegen generate` 后检查生成结果，禁止只修改会被覆盖的生成文件。

本机开发安装的代码身份由平台工具链负责，不进入 Rust。`scripts/local-signing.sh` 只接受登录钥匙串中的 `AirControl Local Code Signing` 和 `com.liuchong.AirControl`；身份缺失、标识不符、严格验证失败或指定要求退化为代码哈希时立即失败。`scripts/install-local.sh` 在替换前完成构建、签名和验证，并保留可恢复的旧应用。普通单元测试继续关闭签名，专门的 `integration_test/stable_local_signing.sh` 才访问个人钥匙串并证明不同构建保持同一指定要求。
