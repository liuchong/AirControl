# 视线辅助原型

## 目标与范围

AirControl 使用 Mac 普通彩色摄像头估计用户注视方向，把光标粗略移动到用户正在看的屏幕区域；用户把右手放回画面后，从当前光标位置进行相对微调并继续使用现有捏合、拖拽和滚动手势。

本轮只交付“视线辅助”，不把普通摄像头包装成专业眼动仪。视线不触发单击、双击、右击或拖拽，不使用眨眼点击，也不保存人脸图像或生物特征。

## 用户可见行为

- 设置区新增“视线辅助”开关，默认关闭。
- 第一次开启且没有有效模型时自动进入九点校准；已有模型时可单独重新校准。
- 校准在目标显示器上依次显示九个注视点。每个点需要稳定注视，进度达标后自动进入下一个点；按 Escape 可取消且不覆盖旧模型。
- 开启控制后，画面中没有可控制的右手或未知手时，可信视线可以粗略移动光标。
- 右手或未知手进入画面后，视线立即停止输出；第一次有效食指移动以当前视线光标为锚点，之后按手部相对位移做精细调整，避免跳回旧的绝对手势位置。
- 左手辅助、捏合点击、拖拽、滚动、抓窗、暂停和安全停止继续使用现有优先级。
- 闭眼、瞳孔缺失、脸部丢失、置信度不足或时间戳无效时不产生视线移动；光标保持原位。
- 切换开关、重新校准、切换显示器和错误恢复都先安全停止控制。

## 业务模型与职责

### 平台外壳（Swift + Vision）

`VisionFrameObservation` 同时携带最多两只手和一个可选的 `StandardGazeSample`。眼部样本只包含左右瞳孔在各自眼框内的归一化平均位置、脸部置信度和闭眼标记，不包含图像。

Swift 负责：

- 从摄像头帧请求手部与面部关键点；视线关闭且不在校准时不运行面部请求。
- 将 Vision 眼睛、瞳孔和脸部置信度转换成原始样本。
- 在所选显示器上展示九点校准界面。
- 持久化是否启用与 Rust 返回的校准系数。
- 只有在辅助功能权限有效时投递 Rust 输出的光标位置。

Swift 不判断注视点映射、不复制置信度阈值、不做眨眼点击。

### 共享核心（Rust）

Rust 新增三个职责：

1. `GazeCalibrationTracker`：按固定九点顺序收集稳定样本。单点需至少两个样本、持续 0.65 秒，样本漂移超过阈值会重新计时；低置信度、闭眼或缺失样本不累计。
2. `GazeProfile` / `GazeMapper`：用九点样本拟合从原始眼部坐标到目标显示器归一化坐标的二维仿射模型，校验模型有限且横纵覆盖足够；运行时按真实时间间隔平滑并将结果限制在显示器边界内。
3. 视线到手势接管：平台投递视线位置前通知现有 `Engine` 更新外部光标锚点。控制手首次产生有效指针位置时不跳动，后续输出“视线锚点 + 手部相对位移 × 精细增益”；再次由视线移动时重新建立锚点。

## 状态与流转

- `关闭`：不请求面部关键点，不加载映射器，现有手势行为不变。
- `待校准`：用户开启但没有有效模型，停止控制并进入九点覆盖层。
- `校准中(stage, progress)`：只收集视线样本，不投递鼠标事件。
- `已启用/等待视线`：映射器存在，但当前样本缺失或不可信，冻结光标。
- `视线粗定位`：无控制手且样本可信，输出平滑光标位置并刷新手部接管锚点。
- `手势精调`：控制手存在，忽略视线输出，现有手势引擎从视线锚点相对接管。
- `取消/失败`：关闭覆盖层；保留旧模型和此前启用状态，没有旧模型则保持关闭。

## 持久化、权限与迁移

- 新增独立的 `UserDefaults` 键保存视线开关和校准模型，不改变 Rust 手势设置 v1 的编码，旧安装自然获得“关闭且未校准”。
- 校准模型只含有限个浮点系数，不含照片、人脸框、眼睛轮廓或身份信息。
- 不新增权限；继续只使用摄像头和辅助功能。
- 目标显示器变化后旧模型仍可映射到新的显示器边界，但用户可重新校准改善精度。

## BDD 验收场景

### 场景 1：默认关闭且不增加处理负担

Given 用户从旧版本升级且没有视线设置，When AirControl 启动，Then 视线辅助显示为关闭，摄像头只运行手部请求，现有手势输出不变。

### 场景 2：九点校准成功

Given 用户开启视线辅助且没有有效模型，When 用户依次稳定注视九个目标点，Then 每点自动推进，Rust 返回有效模型，模型被保存且视线辅助开启。

### 场景 3：无效样本不推进校准

Given 正在校准任一点，When 用户闭眼、瞳孔缺失、置信度不足或视线抖动，Then 当前点进度不完成，不保存无效模型，也不移动光标。

### 场景 4：视线粗定位

Given 视线辅助已校准、控制已开启且画面中没有控制手，When 用户看向目标显示器不同区域，Then 光标按真实时间平滑移动到对应区域且始终位于目标显示器边界内。

### 场景 5：右手无跳动接管

Given 视线刚把光标移动到按钮附近，When 右手进入画面并伸出食指，Then 第一个有效手部指针样本保持当前光标，后续手部位移从该位置相对微调；短捏仍点击微调后的锚点。

### 场景 6：眨眼和丢脸冻结

Given 视线正在控制光标，When 用户眨眼、离开画面或置信度降到阈值以下，Then 不输出新的光标位置，不点击且不进入应用错误状态。

### 场景 7：手势优先且安全释放

Given 视线辅助与现有手势都已启用，When 任一手进入画面、开始捏合、拖拽、左手辅助或过程性抓窗，Then 视线不与手势争夺光标；停止、权限丢失或错误仍通过统一安全停止释放所有状态。

### 场景 8：取消校准不破坏旧模型

Given 已有可用视线模型，When 用户重新校准后按 Escape 取消，Then 旧模型和此前开关状态保持不变，未完成样本不写入持久化。

### 场景 9：隐私边界

Given 视线辅助运行和完成校准，When 检查持久化、网络和文件写入路径，Then 只有开关与数值系数被保存，不存在摄像头帧、人脸或眼部图像写盘和上传。

## 测试落点与 fixture

- Rust 单元测试：九点稳定采样、低置信度/闭眼/抖动、模型校验、屏幕边界、时间平滑、视线到手势相对接管和点击锚点。
- Rust FFI 契约测试：校准器、映射器、无效指针/时间戳、真实 `Engine` 外部光标重定位。
- Swift 单元测试：眼睛/瞳孔纯几何转换、开关与模型持久化、取消保持旧模型。
- `integration_test/`：链接真实 Rust 静态库，执行九点样本到映射结果、视线重定位到右手接管的完整调用链。
- 手动样例：无眼镜、戴眼镜、正常眨眼、轻微头动、明暗环境、目标显示器边缘和双屏。

## 非目标与暂不暴露的预留

- 不实现眨眼点击、注视停留点击、眼控拖拽或文本光标精确定位。
- 不接入 MediaPipe、Windows/Linux 摄像头外壳或外置红外眼动仪；Rust 数据模型保持可复用，但没有对应用户入口。
- 不自动选择网页控件或读取屏幕内容，不申请屏幕录制权限。

## 完成与停止条件

- 新增 BDD 场景对应的 Rust、Swift 和真实 FFI 测试通过，现有全部测试无回归。
- 统一验证通过，README、应用帮助、长期规格、手动验收和 AI-facing 架构记录一致。
- 使用固定本地签名提交后覆盖安装 `/Applications/AirControl.app` 并启动。
- 普通摄像头下的最终精度和眼镜/光照表现由用户真实验收；未达到可用精度时停止在原型结论，不伪称专业眼动控制。
