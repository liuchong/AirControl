# 光标连续性与捏合可靠性优化

## 目标与停止条件

本轮只解决两个已在真实摄像头验收中确认的问题：

1. 食指持续伸出时，某个无关手指关节点短暂低置信度不再中断光标；不同摄像头帧间隔下的平滑响应保持一致。
2. 食指与拇指开始捏合、等待点击和短暂丢点期间不再移动光标；短捏只在锚点单击一次，长捏只在锚点按下一次并在进入拖拽后恢复移动。

停止条件是 Rust 行为测试、C 兼容接口测试、Swift 真实静态库集成测试和统一验证全部通过，新应用安装后可以稳定进入控制状态，最后由用户验收真实移动、单击和拖拽手感。

## 当前代码事实与根因

- HandPoints::from_frame 要求 14 个关节点全部达到最低置信度；无关的无名指或小指丢点会让整帧走丢手路径。
- cursor_for 使用固定的逐帧指数系数；相同动作在不同帧率下具有不同的实际时间响应。
- Engine::process 在判断手势前就更新光标；handle_primary_pinch 在捏合等待阶段仍返回 Move，因此捏合收拢食指必然带动光标。
- 主捏合只用帧数确认，已进入捏合后遇到一次缺点或距离越过退出阈值就立即松开，容易受遮挡和 Vision 抖动影响。

## 核心数据模型

### 可选关键点视图

Rust 从 HandFrame 生成各字段均为可选值的观测视图。每个手势只读取自己需要的点：

- 光标：食指 MCP、PIP、Tip；Tip 必须存在，伸展判断可以在最后一次可靠伸展后的 0.10 秒内保持。
- 主捏合：拇指 Tip、食指 Tip、腕部和中指 MCP。
- 次捏合：拇指 Tip、中指 Tip、腕部和中指 MCP。
- 滚动：食指、中指、无名指和小指各自所需的三点。
- 握拳：四指各自所需的三点。

无关关键点缺失不会让整帧失效。没有足够证据判定某一手势时只跳过该手势；真实丢手仍使用现有 0.20 秒安全时限。

### 光标滤波器

Rust 新增独立的时间感知自适应低通滤波器，输入归一化相机坐标和单调时间戳：

- 首个样本直接建立位置。
- 慢速或静止时使用较低截止频率压制抖动，快速移动时按速度提高截止频率。
- 帧间隔使用真实时间，异常小间隔按 1/240 秒处理，单次滤波间隔最大按 0.10 秒处理。
- 现有 smoothing 仍是唯一用户参数，默认 0.32、范围 0.05 到 1.0；值越大响应越直接。
- 丢手超过 0.20 秒、停止或重建引擎时清空滤波器。

设置版本、持久化 JSON 和 C 兼容 ABI 保持不变。

### 捏合追踪器

主捏合状态为：

idle → arming → pressed → dragging

每个非空状态保存首次捏合时间、最后一次有效捏合证据时间和屏幕锚点。

- idle → arming：第一帧进入阈值，立即记录 last_cursor，并从该帧起禁止 Move。
- arming → pressed：累计两个有效闭合样本；中间缺点最多容忍 0.08 秒。
- arming → idle：在确认前得到可靠张开证据，不产生点击。
- pressed → idle：连续两个可靠张开样本，或有效捏合证据缺失超过 0.08 秒；在锚点产生一次左键按下和释放。
- pressed → dragging：从首次闭合起达到现有 0.35 秒，在锚点产生一次左键按下。
- dragging：只有进入该状态后才重新更新并移动光标；可靠张开或超时丢失时只产生一次释放。

次捏合复用相同的锚点、双样本确认和 0.08 秒证据宽限，但没有拖拽状态。主捏合优先级保持高于次捏合。

进入/退出距离阈值保持 0.28/0.45，不通过放宽阈值掩盖丢点和状态问题。手掌尺度使用最近的可靠值做短时稳定，最长不超过丢手安全时限。

## 决策顺序与失败回退

1. 先处理已处于按下状态的安全释放和丢手超时。
2. 有完整可靠证据时处理握拳暂停。
3. 更新主/次捏合追踪器；任何捏合候选或已激活状态都抑制普通指针移动。
4. 没有捏合时再判断滚动和普通指针。
5. 指针 Tip 缺失时保持实际系统光标不动，不外推预测位置。
6. 未知关节类型、非法指针、非有限时间戳和非法缓冲区仍是调用错误；单个已知关节点无效仍按缺失数据处理。

## BDD 验收场景

### 场景 1：无关关节点缺失

Given 食指三点可靠且保持伸展，无名指 Tip 低于置信度阈值，When Rust 处理该帧，Then 仍产生一个光标移动命令，不进入丢手状态。

### 场景 2：帧率变化

Given 同一条食指轨迹分别以 15 FPS 和 30 FPS 输入，When 使用默认平滑设置处理，Then 两条轨迹在相同实际时间的输出位置差不超过屏幕宽度的 2%，且都不会直接跳到目标。

### 场景 3：捏合进入不移动

Given 光标已经由食指定位，When 食指向拇指收拢并改变了食指 Tip 坐标，Then 从第一帧捏合候选起不产生 Move，短捏松开只在原锚点产生一次左键按下和释放。

### 场景 4：捏合短暂缺点

Given 主捏合已经得到一个有效闭合样本，When 拇指 Tip 短暂缺失且在 0.08 秒内重新闭合，Then 捏合继续确认且不提前点击、不移动光标；可靠松开后只点击一次。

### 场景 5：长捏拖拽

Given 主捏合已确认，When 保持到 0.35 秒，Then 在锚点只按下一次左键；之后移动捏合手才产生拖拽移动，松开只释放一次。

### 场景 6：拖拽丢手

Given 左键已按下进入拖拽，When 控制所需关键点缺失并超过安全时间，Then 释放左键一次、清空捏合和滤波状态，不产生预测移动。

### 场景 7：真实跨语言路径

Given 包含无关关节点低置信度、捏合坐标偏移和短暂拇指缺失的 fixture，When Swift 经真实 C 兼容接口调用 Rust，Then 抽象命令的种类、次数和锚点坐标与上述场景一致。

## 权限、持久化与安装

- 不新增摄像头以外的采集，不写盘、不联网。
- 不新增权限；仍只有摄像头和辅助功能。

- 完整验证后使用 `AirControl Local Code Signing` 固定身份重新构建并替换 `/Applications/AirControl.app`。首次从旧临时签名迁移时允许重新授权一次；后续覆盖安装不得回退临时签名，详细边界见 `docs/changes/stable-local-signing.md`。

## 非目标与预留

- 本轮不新增捏合灵敏度界面、不改变进入/退出阈值、不重构 Swift 摄像头并发链路。
- 本轮不实现预测式补帧；关键点缺失时保持光标不动，避免错误外推。
- 若本轮后仍有整帧处理延迟，再单独测量 Vision、主线程发布和预览绘制耗时；该性能重构不以半成品入口暴露。
