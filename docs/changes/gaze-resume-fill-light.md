# 视线校准恢复与屏幕辅助光源

## 目标与范围

本次修复九点视线校准结束后丢失控制意图的问题，并新增只属于 macOS 外壳的屏幕边缘辅助光源。辅助光源用目标显示器边缘的白色/暖色柔光改善普通摄像头前的人脸照明，不改变 Rust 手势与视线算法，不新增权限。

## 业务设计

- 校准会话记录一个布尔状态 `校准前是否正在控制`。它只能在开始校准时写入一次，在成功、取消、失败后清空。
- 开始校准仍先走统一安全停止，确保鼠标按键、抓窗和暂停状态全部释放。
- 校准成功且开始前正在控制时，只有摄像头与辅助功能权限都仍有效，才通过与“开启控制”按钮相同的摄像头重连路径恢复；否则停在仅预览，绝不绕过权限。
- 校准开始前未控制、用户取消、模型无效或处理失败时都不自动开启控制。旧模型和旧启用状态继续按既有规则保留。
- 辅助光源设置包含 `enabled`、`brightness`、`warmth`。默认关闭，默认亮度 35%，默认色温为中性偏暖；读取到越界或非有限数值时回退安全默认值。
- 设置独立保存到 `UserDefaults`，不进入 Rust 设置版本，也不跨平台共享。开关和滑杆变化即时更新目标显示器上的无焦点透明覆盖层。
- 覆盖层只绘制屏幕边缘柔光、忽略鼠标事件、不激活应用、不读取屏幕内容。切换显示器和显示器热插拔时重新定位；关闭或退出时立即移除。
- 摄像头绿色隐私指示灯由 macOS 控制，本功能不尝试关闭或遮蔽它。

## BDD 验收场景

### 场景 1：控制中完成九点校准后自动恢复

Given 用户开始校准前正在控制且两项权限有效，When 九点模型成功保存，Then 覆盖层关闭，并通过统一摄像头重连流程回到控制中，不需要再次点击“开启控制”。

### 场景 2：预览状态完成校准不误启动

Given 用户开始校准前只是预览，When 九点模型成功保存，Then 视线辅助被启用但应用仍为仅预览，不投递鼠标事件。

### 场景 3：取消、失败和权限变化不误启动

Given 校准前正在控制，When 用户取消、模型无效、校准处理失败，或完成时任一权限已失效，Then 应用保持停止并清空恢复意图；后续重新校准不会继承过期意图。

### 场景 4：辅助光源默认安全关闭并持久化

Given 用户从旧版本升级，When 应用启动，Then 辅助光源默认关闭；When 用户开启并调整亮度与冷暖色后重启，Then 三项设置恢复。

### 场景 5：损坏设置安全回退

Given 持久化亮度、冷暖色不是有限数值或越界，When 应用读取设置，Then 使用默认关闭、35% 亮度和默认冷暖色，不创建异常覆盖层。

### 场景 6：辅助光源不干扰电脑操作和校准

Given 辅助光源已开启，When 用户操作目标显示器或进行九点校准，Then 柔光层不接收鼠标、不抢键盘焦点，校准目标仍在其上方可见且 Escape 仍能取消。

### 场景 7：关闭状态不会被校准或恢复流程绕过

Given 辅助光源开关未选中，When 应用启动、开始九点校准、校准后恢复控制、摄像头重连或显示器变化，Then 所有入口都重新应用当前关闭设置，不创建、显示或重新置前柔光层。只有用户明确打开开关后，柔光层才允许显示。

## 测试落点

- Swift 单元测试：校准恢复决策的成功、取消、失败、权限边界和一次性消费；辅助光源默认值、持久化、损坏数据回退，以及校准刷新不能绕过关闭状态。
- `integration_test/`：从“控制中开始校准”到成功恢复请求的完整状态序列，以及辅助光源设置跨 `SettingsStore` 重载。
- 手动验收：真实摄像头完成九点校准后无需再次点击即可控制；开启柔光后仍能点击屏幕边缘内容、切换显示器并按 Escape 取消校准。

## 非目标与停止条件

- 不关闭 macOS 摄像头绿色隐私灯，不申请屏幕录制权限。
- 不把 `NSPanel`、显示器或 `UserDefaults` 逻辑放进 Rust；跨平台共享层没有可复用业务规则，因此本轮 Rust 生产代码不变。
- 不实现自动环境光测量或根据人脸曝光自动调光。
- 单元测试、`integration_test/`、统一验证、隐私静态检查通过，并完成固定签名安装重启后停止开发，交给用户进行真实光照验收。
