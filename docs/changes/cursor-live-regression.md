# 光标实时控制回归修复

## 用户目标与停止条件

修复真实摄像头测试中“开启控制后光标不移动”的问题。完成条件是：摄像头偶发产生单个无效关节点时应用不进入错误状态；手掌横放或旋转时，伸出的食指仍产生光标移动；真实握拳保持 0.70 秒仍能安全暂停；真实处理错误在界面显示具体原因；自动验证通过并重新安装、重启应用等待用户验收。

## 行为设计

- Rust 共享核心继续拥有关键点有效性、手势分类、时序与安全释放的唯一业务实现。
- C 兼容接口把坐标、置信度非有限或不在 `0...1` 的单个关节点视为当前帧中的缺失测量。剩余有效点仍交给状态机；关键点不足时沿用丢手计时和安全释放，不返回整帧错误。
- 空引擎、空输出计数、未知关节类型、非有限时间戳和非法输出缓冲区仍属于调用错误，返回 `AC_STATUS_INVALID_ARGUMENT`。
- 四指状态使用 `MCP → PIP → Tip` 三点的相对方向和长度判断，不使用图像纵轴；因此同一姿势旋转后语义不变。
- 握拳仍需四指均折叠并稳定保持 0.70 秒才切换暂停，且张手后才能再次触发。
- Swift 只展示 Rust 或平台错误的文字，不复制任何关节点清洗或手势判断。
- 不改变持久化结构、默认设置、权限、安装位置或跨语言接口版本。

## BDD 验收场景

### 场景 1：越界测量不终止控制

Given Vision 返回一帧包含 14 个已知关节点且其中一个坐标越界，When Swift 经真实 C 兼容接口调用 Rust 核心，Then 调用成功、该点按缺失处理，并且应用不进入错误状态。

### 场景 2：结构性调用错误仍被拒绝

Given 输入包含未知关节类型或空的必需接口指针，When 调用 Rust 核心，Then 返回参数无效，避免掩盖平台程序错误。

### 场景 3：横向食指移动光标

Given 手掌相对画面旋转且只有食指沿手掌方向伸出，When 连续处理手部帧，Then Rust 输出移动命令，不输出暂停命令。

### 场景 4：真实握拳仍安全暂停

Given 四指相对各自关节均折叠，When 姿势稳定保持 0.70 秒，Then 只切换一次暂停；张手前不会重复切换。

### 场景 5：错误详情可见

Given 摄像头或处理链路产生真实错误，When 应用进入错误状态，Then 主窗口同时显示“发生错误”和具体错误文字，不产生鼠标事件。

## 测试落点与样例

- Rust 行为测试：水平食指、旋转无关判断、握拳安全时序。
- Rust C 兼容接口测试：单个越界/非有限测量被忽略；未知类型和空指针仍失败。
- Swift `integration_test/`：通过真实 Rust 静态库验证水平食指和越界测量。
- Swift 单元测试：错误状态保留并提供具体文字。

## 非目标

本次不开发 Windows/Linux 图形界面，不增加新手势、权限或配置项，不改变校准交互，也不引入新的姿态检测模型。未来平台只需向现有 C 兼容接口提供同一标准关节点；本次不暴露未实现的平台入口。
