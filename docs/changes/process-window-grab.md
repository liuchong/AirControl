# 过程性隔空抓窗

## 目标、范围与停止条件

本轮新增右手“张掌 → 收拢 → 握拳”的过程性隔空抓窗：右手先稳定张开，随后在限定时间内逐步收拢并稳定握拳，才抓住当前光标下的窗口；握拳单独出现在画面中绝不触发。抓住后用右手掌心相对位移移动窗口和光标，重新张开手、丢手超时、左手暂停、停止或错误都会安全结束抓窗。

停止条件是：Rust 状态机、C 兼容接口、Swift 命令路由、macOS 辅助功能窗口控制、真实静态库跨语言样例、帮助与长期规格全部同步并通过统一验证；固定签名版本覆盖安装后，用户可在真实摄像头下验收任意窗口区域抓取。

## 直接相关硬规则

- “任何方案要等用户确定方可执行”——过程性抓握、右手单独可用和重新张掌释放已经由用户确认。
- “实现前必须写出清晰的 `Given / When / Then` 验收场景”。
- “只要行为可测试，必须先把 BDD 场景转成失败测试或可执行验证，再改生产代码”。
- “保证每一个逻辑开发、逻辑修改的集成测试覆盖率是最高优先级硬规则”。
- 跨语言同一业务必须按职责矩阵对齐模型、命令、失败语义、样例、文档与验证。
- Rust 是平台无关业务规则的唯一实现；Swift 只提供 Vision 手别、macOS 权限和操作系统事件投递。
- 安装前必须完成验证；本机安装继续使用固定签名身份，不得回退到临时签名。

## 核心状态与决策规则

Rust 共享核心维护独立的 `idle / openCandidate / armed / closing / grabbed` 抓窗状态，并保存张掌稳定计时、收拢截止时间、连续握拳样本、掌心基准和屏幕光标基准。

1. 只有明确识别的右手可以启用抓窗；未知手仍可普通控制，但不能抓窗。
2. 四指全部伸展连续出现至少两帧且持续 0.12 秒后进入 `armed`。进入后保存当前屏幕光标和右手掌心，并抑制普通指尖移动，避免收拢手指把目标带偏。
3. `armed` 后必须观察到伸展手指数下降，才算开始 `closing`；画面中直接出现的拳头没有此前张掌过程，不得触发。
4. 从开始收拢起 0.65 秒内，四指折叠连续确认两帧，输出一次“开始抓窗”。超时、重新完全张开或证据不足会取消本次候选，不产生系统操作。
5. 连续两帧拳头确认抓取时，以当前拳头掌心重新落定移动基准，但保留张掌时冻结的屏幕光标锚点，避免收拢动作造成窗口首帧跳动。抓住后以右手掌心相对位移控制屏幕位置，输出绝对目标坐标。平台层以“窗口初始位置 + 目标光标相对抓取锚点的位移”设置窗口位置，并把光标同步移动到目标坐标。
6. 抓住后四指重新伸展连续确认两帧，输出一次“结束抓窗”；右手整手丢失超过 0.20 秒也结束。
7. 左手握拳暂停优先级最高：进入暂停前先结束抓窗。任何已稳定的左手辅助模式都会阻止新的抓窗候选；已有抓窗在左手辅助模式进入时结束。
8. 普通主捏拖拽与抓窗互斥。抓窗候选和抓住期间不运行普通捏合、滚动或食指移动状态机，因此不会额外产生点击或鼠标按下。

## 抽象命令与平台执行

C 兼容接口升级为 ABI 第 4 版，新增三种命令：

- `WindowGrabBegin(x, y)`：在抓取锚点开始。Rust 保证每次会话只输出一次。
- `WindowMove(x, y)`：抓住期间的绝对屏幕目标坐标。
- `WindowGrabEnd`：结束当前抓窗会话；停止和安全释放也必须生成。

macOS 平台控制器使用辅助功能接口在 `(x, y)` 找到最上层元素及其所属窗口，检查窗口位置属性可写，记录窗口初始位置和抓取锚点。移动时只设置该窗口的位置属性，不模拟鼠标按下，因此可从应用内容区任意位置抓窗，也不会触发内容控件。平台失败分两类：

- 光标下没有窗口、窗口位置不可写、全屏或系统表面拒绝移动：本次抓窗静默取消，继续保持 AirControl 控制。
- 辅助功能授权丢失或系统事件投递发生真实错误：沿现有 `safeStop()` 路径结束所有抓窗和鼠标状态，并显示具体错误。

不新增系统权限。仍只使用摄像头权限和已有的 macOS 辅助功能权限；不读取窗口内容、不申请屏幕录制。

## BDD 验收场景

### 场景 1：单独拳头绝不触发

Given 引擎处于空闲且没有先看到稳定张掌，When 右拳连续出现任意时长，Then 不输出开始抓窗、鼠标点击、暂停或辅助模式命令。

### 场景 2：完整过程只开始一次

Given 右手张掌连续稳定 0.12 秒，When 伸展手指数逐步下降并在 0.65 秒内连续两帧成为拳头，Then 在张掌时保存的光标锚点输出且只输出一次开始抓窗。

### 场景 3：收拢过程锁定目标

Given 抓窗已经武装，When 食指在收拢时明显移动，Then 不输出普通 Move；最终开始抓窗仍使用武装前的光标锚点。

### 场景 4：掌心移动窗口和光标

Given 已开始抓窗，When 握拳确认后掌心保持不动，Then 收拢过程中积累的掌心偏移不会移动窗口；When 随后横向或纵向移动掌心，Then Rust 输出对应的绝对屏幕目标，macOS 以相同位移更新窗口位置并同步移动光标，不产生鼠标按下、释放或点击。

### 场景 5：重新张掌释放

Given 窗口已经抓住，When 右手重新张开并连续确认两帧，Then 只输出一次结束抓窗；继续保持张掌不会重复结束或立即重新抓取。

### 场景 6：候选超时或反向动作取消

Given 张掌已武装，When 收拢未在 0.65 秒内完成，或收拢后重新完全张开，Then 取消候选且不输出任何窗口命令。

### 场景 7：丢手、停止和错误安全结束

Given 窗口已经抓住，When 右手丢失超过 0.20 秒、用户停止、Vision 不可恢复错误或应用退出，Then 只输出/执行一次结束抓窗并清空会话；重新开始后不存在旧窗口引用。

### 场景 8：左手优先且不冲突

Given 左手辅助模式已生效，When 右手完成张掌到握拳，Then 不开始抓窗；Given 正在抓窗，When 左手握拳达到暂停阈值或其他辅助模式稳定进入，Then 先结束抓窗，再进入对应左手行为。

### 场景 9：不可移动窗口软失败

Given 光标下没有可移动窗口或位置属性不可写，When 收到开始抓窗命令，Then macOS 清空本地窗口会话、忽略后续移动直到结束，不停止 AirControl，也不模拟内容点击。

### 场景 10：真实跨语言路径

Given 样例包含稳定张掌、逐步收拢、两帧拳头、掌心移动、重新张掌和丢手，When Swift 通过真实 C 兼容接口调用 Rust 静态库，Then 命令种类、顺序、锚点、移动坐标和结束次数与上述规则一致。

## TDD 测试与样例落点

- `crates/aircontrol-core/tests/window_grab_behavior.rs`：完整状态流、拳头单独出现、锚点锁定、超时/反向取消、左手冲突、丢手/停止安全结束。
- `crates/aircontrol-core/tests/ffi_contract.rs`：ABI 第 4 版、新命令字段与输出容量失败时的事务语义。
- `Tests/AirControlTests/WindowControllerTests.swift`：窗口初始位置与抓取锚点的位移计算、不可移动窗口软失败、结束清理和命令路由。
- `integration_test/fixtures/window_grab.json` 与 `GestureFixtureTests.swift`：经真实 Rust 静态库验证开始、移动、结束完整路径。
- `scripts/verify.sh`：继续作为 Rust、Swift、跨语言和构建的统一验证入口。

## 跨语言职责矩阵

| 职责 | Rust 共享核心 | Swift/macOS 对应 | 目的、门禁与允许差异 |
|---|---|---|---|
| 张掌、收拢、握拳时序与冲突优先级 | `window_grab.rs`、`engine.rs` | 无平台算法 | Rust 单侧业务实现；Swift 不复制阈值或姿势判断，Rust 行为测试与真实跨语言样例证明生产路径。 |
| 抓窗命令模型 | `engine.rs`、`ffi.rs` | `CoreEngine.swift` | 开始/移动/结束种类与坐标逐字段一致；ABI、解码和样例同批验证。 |
| 窗口定位与移动 | 只输出屏幕坐标 | `SystemWindowController.swift` | macOS 辅助功能接口是平台必要差异；Swift 只执行窗口命令，不决定手势成立。 |
| 光标同步与安全释放 | Rust 决定何时输出移动/结束 | `SystemCursorController.swift`、`AppModel.swift` | 平台路由按命令顺序执行；停止时 Rust 先结束，平台再兜底清理本地窗口引用。 |
| 权限和失败语义 | 不访问系统权限；命令保持平台中立 | `PermissionManager.swift`、窗口控制器 | 仍用辅助功能授权；不支持的窗口软失败，授权丢失走现有硬失败。 |
| 用户说明与长期记录 | 状态机和测试作为事实 | `HelpView.swift`、README、长期规格、`.agents` | 操作方法、限制、ABI 和验证结果必须同步，不暴露未实现设置。 |

## 配置、持久化与安装影响

- 本轮阈值是共享核心固定默认行为，不新增设置项或迁移；用户已有平滑、手势开关、摄像头和显示器选择不变。
- 抓窗属于不可单独关闭的右手过程动作；它只在普通模式下候选，不改变现有五个手势开关的位含义。
- 不持久化窗口引用、窗口位置或抓窗状态；每次停止都会清空。
- 完整验证后用 `AirControl Local Code Signing` 和 `com.liuchong.AirControl` 覆盖安装，不新增权限，不刷新已有授权身份。

## 非目标与暂不实现的预留接口

- 不实现窗口缩放、贴边吸附、最小化、最大化、跨空间移动或多窗口编组。
- 不强行移动全屏窗口、菜单栏、桌面、Dock 或位置属性不可写的系统窗口。
- 不增加左手参与抓窗的第二套映射，也不提供抓窗灵敏度设置；真实手感有问题后再基于测试证据调整。
- 不为 Windows/Linux 编写平台窗口控制器；本轮只保证 Rust 命令语义可复用，未来外壳实现各自的系统窗口接口。
