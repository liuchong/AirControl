# 左手辅助、失控恢复与品牌统一

## 目标、范围与停止条件

本轮完成三个相互独立但共同影响真实使用体验的结果：

1. macOS Vision 同时识别左右手；左手提供稳定器、光标锁定、双击修饰、掌控滚动、拖拽辅助和握拳暂停，右手继续负责指向与点击。左手不出现时完整保留现有单手行为。
2. 解决控制一段时间后突然失效且“停止/开始”也无法恢复的问题：用户停止必须清空 Rust 暂停会话；连续 Vision 失败只能进入可恢复挂起，摄像头继续采集；真正的摄像头错误在下一次开始时必须重新配置并启动。
3. 建立统一 AirControl 品牌：应用图标使用“气流双翼 + 光标箭头 + A”，状态栏使用同源的单色模板轮廓，README 展示品牌图。

停止条件是 Rust 行为测试、C 兼容接口测试、Swift 单元测试、真实静态库跨语言 fixture、统一验证和固定签名安装检查全部通过；安装后的应用能够显示新品牌并进入可由用户验收的双手控制状态。

## 直接相关硬规则

- “任何方案要等用户确定方可执行”——本方案及六项左手功能已由用户确认。
- “实现前必须写出清晰的 `Given / When / Then` 验收场景”。
- “只要行为可测试，必须先把 BDD 场景转成失败测试或可执行验证，再改生产代码”。
- “保证每一个逻辑开发、逻辑修改的集成测试覆盖率是最高优先级硬规则”。
- “优先完成用户真正要使用的主链路；不得为了形式化完整、文档外观、审查数量或非阻塞改进无限扩项”。
- 跨语言同一业务必须用职责矩阵对齐模型、状态、命令、失败语义、fixture、文档与验证；平台单侧代码必须说明其不可共享的原因。
- Rust 是平台无关业务规则的唯一实现；Swift 只识别手、转交标准关键点、执行抽象命令和维护 macOS 生命周期。

## 当前代码事实与根因

- Vision 请求当前 `maximumHandCount = 1`，并只返回第一只手，没有把生理左右手信息传给 Rust。
- Rust `Engine::process` 只有单手帧，右手握拳会切换暂停；`Engine::stop` 保留 `paused`。Swift `safeStop` 只清自己的 `gesturePaused`，所以停止后重开仍可能被 Rust 保持在暂停状态。
- 连续五次 Vision 处理失败时，Swift 同时执行 `safeStop()` 与 `camera.stop()`；而 `toggleControl()` 只修改控制布尔值，不重新配置或启动摄像头，因此用户无法用停止/开始恢复。
- 短捏点击目前用分离的 MouseDown/MouseUp 表示，没有可跨平台表达系统双击次数的命令。
- 应用和状态栏仍使用系统手势符号，没有项目资产目录和统一品牌标记。

## 核心数据模型

### 双手帧

Rust 接收同一时间戳下最多两只手，每个标准关节点携带 `left`、`right` 或 `unknown` 生理手别。关节集合新增拇指掌指关节和指间关节，用于区分左手竖拇指与握拳。

- 已识别的右手负责普通单手控制和所有右手动作。
- 没有已识别右手时，唯一一只 `unknown` 手可作为普通单手控制手，避免手别偶发不确定导致失控。
- `unknown` 永远不能成为左手辅助控制手，因此不会误触发暂停、锁定、拖拽或双击修饰。
- 已识别左手只负责辅助姿势，不直接沿用右手单手手势。

### 左手辅助状态

共享核心维护 `none / precision / cursorLock / doubleClick / scroll / drag` 六个稳定辅助模式，以及独立的左手握拳暂停锁存状态。

- 新姿势连续出现至少 0.12 秒且至少两个有效样本后才能进入。
- 左手短暂遮挡不超过 0.20 秒时保留当前模式；超时退出。
- 冲突姿势优先级为：握拳暂停、食指锁定、竖拇指双击、三指拖拽、V 形滚动、张掌稳定。
- 退出任何模式都清空相对移动/滚动锚点；退出拖拽必须先释放左键。
- 左手丢失或右手丢失超过 0.20 秒时，拖拽辅助都必须释放左键。

### 显式点击命令

抽象命令新增 `Click(button, x, y, count)`。普通短捏为 `count=1`，左手竖拇指修饰下的右手主捏为 `count=2`。macOS 投递器用 Core Graphics 的点击次数元数据生成真正的单击或双击；拖拽仍使用独立的按下/释放命令。

### 可恢复识别状态

Swift 维护用户控制意图与 Vision 暂停原因，而不是把连续识别失败等同于用户停止：

- 正常控制中连续五帧 Vision 抛错：每帧仍向 Rust 转交空手以推进安全释放；第五帧释放所有按键并进入 `recovering`，但不停止摄像头，也不清除用户控制意图。
- `recovering` 中连续两帧成功：自动恢复 `controlling`，第二帧开始重新交给 Rust；中间任何失败都会重新计数。
- 用户主动停止：清除恢复计数、控制意图和 Rust 暂停状态，释放全部按键，保留摄像头预览。
- 真正摄像头运行错误：安全停止并停止捕获；下一次用户开始时重新配置所选摄像头后再启动，不依赖旧会话仍可用。

## 六项左手行为与决策规则

1. **张开左掌——精准稳定器**：进入时记录当前系统光标与右手掌心；之后用右手掌心的相对位移控制光标，增益为普通屏幕映射的 40%，并使用独立的平滑器。右手手指收拢、捏合或改变姿势不改变指向基准；点击手势可叠加在同一模式上。
2. **左手只伸食指——光标锁定**：不再输出移动命令；右手主捏、次捏仍在当前固定位置产生左键和右键点击。
3. **左手竖拇指——双击修饰**：右手一次主短捏产生一次 `count=2` 左键点击；没有主捏时右手仍按普通单手方式移动。
4. **左手 V 形——掌控滚动**：忽略右手指型和点击，使用右手掌心纵向相对位移输出滚动；模式退出时清空滚动锚点。
5. **左手三指——拖拽辅助**：模式稳定且检测到右手掌心后按下左键；右手掌心相对移动光标；左手姿势退出、任一手超时丢失、暂停、停止或错误时只释放一次。
6. **左手握拳保持——暂停/恢复**：稳定保持现有 0.70 秒后切换暂停；右手握拳不再暂停。必须先离开握拳姿势，下一次保持才可再次触发。

左手不存在时，右手继续使用既有食指移动、主捏单击/拖拽、次捏右键和双指滚动。已有捏合锚点、双样本确认、0.08 秒丢点宽限和时间感知平滑不变。

## BDD 验收场景

### 场景 1：左掌稳定器不受捏合手指位移影响

Given 左掌张开已稳定进入精准模式且右手掌心不动，When 右手食指和拇指完成一次短捏，Then 光标不因指尖收拢发生跳动，并在当前锚点产生一次单击。

### 场景 2：左手锁定后精准点击

Given 左手只伸食指已稳定且光标位于目标，When 右手移动并完成主捏或次捏，Then 不产生 Move，分别在固定位置产生一次左键或右键点击。

### 场景 3：竖拇指产生真实双击

Given 左手竖拇指已稳定，When 右手完成一次主短捏，Then Rust 只输出一个 `count=2` 左键 Click，Swift 将点击次数写入系统事件；不会输出两个相互独立的单击猜测。

### 场景 4：V 形掌控滚动

Given 左手 V 形已稳定，When 右手保持任意指型并上下移动掌心，Then 只产生与掌心纵向位移对应的滚动命令，不产生点击。

### 场景 5：三指拖拽安全释放

Given 左手三指已稳定且右手掌心存在，When 模式进入并移动右手，Then 左键只按下一次且光标跟随；When 左手或右手丢失超过 0.20 秒，Then 左键只释放一次。

### 场景 6：只有左手握拳可暂停

Given 正在控制，When 右手握拳保持超过 0.70 秒，Then 不切换暂停；When 左手握拳保持超过 0.70 秒，Then 切换暂停且显示“左手握拳暂停”。

### 场景 7：停止后新会话清除暂停

Given 左手握拳已把 Rust 核心切到暂停，When 用户停止后重新开始并伸出右手食指，Then Rust 不再保持旧暂停状态并立即产生移动命令。

### 场景 8：连续 Vision 失败自动恢复

Given 用户正在控制，When 连续五帧 Vision 处理失败，Then 释放按键并显示“摄像头识别恢复中”，摄像头继续采集；When 随后连续两帧成功，Then 自动回到控制中且无需用户点击停止/开始。

### 场景 9：摄像头错误后的开始是真正重试

Given 捕获会话发生运行错误并安全停止，When 用户再次开始控制，Then 应用重新配置所选摄像头并启动会话，只有成功后才进入控制中。

### 场景 10：未知手别安全边界

Given Vision 只给出 `unknown` 手，When 该手做张掌、握拳或三指姿势，Then 可继续普通单手指向与点击，但绝不进入任何左手辅助模式。

### 场景 11：真实跨语言路径

Given 双手 fixture 包含稳定左掌、左手竖拇指、右手短捏和手丢失，When Swift 经真实 C 兼容接口调用 Rust，Then辅助模式变化、移动、单击/双击和安全释放的种类、次数、坐标与上述规则一致。

## 跨语言职责矩阵

| 职责 | Rust 共享核心 | Swift/macOS 对应 | 目的、门禁与允许差异 |
|---|---|---|---|
| 双手与手别模型 | `model.rs`、`ffi.rs` | `HandPoseEstimator.swift`、`CoreEngine.swift` | 两端同为 left/right/unknown 和 16 个关节；Swift 只转换 Vision 名称，FFI 测试逐字段验证。 |
| 左手姿势与稳定状态 | `bimanual.rs`、`engine.rs` | 无平台算法 | 合理的 Rust 单侧业务实现；Swift 不复制姿势阈值，真实 fixture 验证生产路径。 |
| 相对移动、模式优先级与安全释放 | `engine.rs`、`cursor_filter.rs` | `SystemCursorController.swift` 只执行命令 | Rust 决定何时移动/滚动/按下/释放；Swift 二次权限门禁不改变语义。 |
| 单击与双击 | `engine.rs`、`ffi.rs` | `CoreEngine.swift`、`SystemCursorController.swift` | Click 的 button/坐标/count 逐项一致；仅 macOS 用 Core Graphics 字段投递，属于平台必要差异。 |
| 识别失败恢复 | Rust `stop` 清除会话暂停并安全释放 | `VisionFailureTracker.swift`、`AppModel.swift`、`CameraService.swift` | 共享核心保证新会话干净；摄像头生命周期是 macOS 单侧平台职责，Swift 测试其纯状态机。 |
| 用户状态与帮助 | 命令中的辅助/暂停状态 | `MainView.swift`、`HelpView.swift`、`AirControlApp.swift` | 用户显示必须与 Rust 命令一致，不在界面猜手势。 |
| 品牌与图标 | 无 | `Assets.xcassets`、状态栏模板资源、`README.md` | 纯平台/展示资产，无跨平台业务对应；同源轮廓与验证脚本防止遗漏。 |
| 长期规格与测试证据 | `docs/specs/air-control.md`、Rust 测试 | README、应用帮助、Swift/集成测试、`.agents` | 行为、权限、失败语义、fixture 名和验证命令同步。 |

## 权限、持久化、配置与安装

- 不新增权限、不联网、不录制、不保存摄像头画面；仍只需要摄像头和辅助功能。
- 六项左手映射是本轮固定默认行为，不新增自定义快捷键或设置迁移；未知未来设置字段不对用户暴露。
- 现有控制区域、平滑、捏合阈值、显示器 ID 和摄像头 ID 持久化保持不变。
- C 兼容接口因双手/手别和 Click 命令升级到 ABI 第 3 版；Rust、头文件、Swift 和 fixture 必须同批升级。
- 完整验证后继续使用 `AirControl Local Code Signing` 与 `com.liuchong.AirControl` 固定身份安装；不申请新权限、不删除现有系统授权、不回退临时签名。

## 非目标与暂不实现的预留接口

- 本轮不实现左手水平挥动切换显示器；只在设计中保留未来动作类别，不在代码、设置、帮助或测试中暴露半成品。
- 本轮不实现左手拇指与食指间距调速；同样不提供入口或隐藏开关。
- 本轮不支持自定义左手动作映射、键盘组合键、启动应用、全身动作、多人控制或 Windows/Linux 外壳。
- 本轮不增加第三方手势模型；Vision 是 macOS 检测器，Rust 接口保持可由未来平台检测器提供同一标准双手帧。
- 品牌首轮只交付应用图标、状态栏模板图标和 README 标记，不扩展网站、宣传物料或完整视觉规范。
