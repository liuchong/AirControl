# AirControl 长期行为规格

## 目标与边界

AirControl 第一版是原生 macOS 应用，并以 Windows/Linux 后续外壳可以复用同一业务核心为架构边界。它只在用户明确开启控制、摄像头已授权、辅助功能已授权时，将摄像头内的有效手势或用户主动启用并校准的视线辅助转换为本机鼠标事件。

第一版支持 macOS 14 及以上版本，同时识别最多两只手。右手或无法确定左右的单手负责普通控制；只有明确识别为左手的姿势才能启用双手辅助。应用不录制、不保存、不上传摄像头画面，不访问麦克风、屏幕内容或网络。

非目标：本轮交付 Windows/Linux 应用、全身动作、多人识别、键盘输入、按手势启动应用、云端识别、自定义机器学习模型、眨眼/注视点击、专业红外眼动仪和 Mac App Store 发布。平台层保留未来接入其他姿态与眼部检测器的内部扩展点；未实现能力不得出现在用户界面或帮助文案中。

## 跨平台职责边界

| 职责 | Rust 共享核心 | Swift macOS 外壳 | 一致性门禁与允许差异 |
|---|---|---|---|
| 关键点、手别模型与校验 | `crates/aircontrol-core/src/model.rs` | `AirControl/Vision/HandPoseEstimator.swift` | Swift 只做 Vision 关节名、坐标和系统手别转换；置信度、控制手选择和未知手安全规则只在 Rust 判断。 |
| 手势、双手辅助、过程性抓窗、时序与安全释放 | `crates/aircontrol-core/src/engine.rs`、`bimanual.rs`、`pinch.rs`、`window_grab.rs` | `AirControl/Core/CoreEngine.swift` | Rust 是唯一业务实现；Swift 只转发各手帧和执行返回命令。 |
| 坐标、平滑与校准 | `crates/aircontrol-core/src/cursor_filter.rs`、`geometry.rs` | `AirControl/App/AppModel.swift` | Swift 提供显示器边界；算法、阈值和校准合法性只在 Rust。 |
| 视线辅助、九点模型与手势接管 | `crates/aircontrol-core/src/gaze.rs`、`engine.rs` | `AirControl/Vision/GazeGeometry.swift`、`AirControl/Core/GazeController.swift` | Swift 只提取眼框内瞳孔位置、显示校准点和执行坐标；稳定采样、模型拟合、平滑、冻结及相对接管只在 Rust。 |
| 设置默认值和校验 | `crates/aircontrol-core/src/settings.rs` | `AirControl/Settings/SettingsStore.swift` | Rust 产生/校验设置；Swift 只负责版本化持久化与平台设备 ID。 |
| 跨语言边界 | `crates/aircontrol-core/src/ffi.rs` | `AirControl/Core/CoreEngine.swift` | `include/aircontrol_core.h` 是双方共同契约；必须有 ABI 版本和错误路径测试。 |
| 摄像头与姿态检测 | 无平台实现 | `AirControl/Camera/*`、`AirControl/Vision/*` | 合理的单侧平台代码；输出必须收敛为同一关键点模型。 |
| 权限、鼠标、窗口与界面 | 只输出抽象命令 | `AirControl/Input/*`、`AirControl/UI/*` | 合理的单侧平台代码；`SystemWindowController` 只执行 macOS 窗口定位和移动，不得在 Swift 重做手势决策。 |

Rust 核心不访问摄像头、文件、网络、操作系统权限或鼠标接口。跨语言接口采用无依赖的 C 兼容数据结构和不透明引擎句柄，不把 Rust 内存所有权暴露给 Swift。

## 用户可见入口

- 主窗口：摄像头预览、手部关键点、权限状态、运行状态、手势状态、摄像头与显示器选择、校准和参数设置。
- 菜单栏：显示当前状态，并提供开启、暂停、打开窗口和退出。
- 全局紧急快捷键：`Control + Option + Command + A`，只能停用或重新开启已具备权限的控制。
- 帮助菜单：手势说明、权限说明、隐私和安全停止方法。

本项目没有面向用户的命令行入口，因此 `/help` 与 `--help` 不适用；同一信息由应用内帮助和 README 提供。

## 核心数据模型

### 手部帧 `HandPoseFrame`

- `timestamp`：单调递增时间，单位为秒。
- `joints`：关键点名称到归一化坐标、置信度的映射。
- 坐标原点在图像左下角，有效范围为 0 到 1。已知关节的单个坐标或置信度非有限、越界时，该测量按当前帧缺失处理，不让整帧进入错误状态。
- 置信度低于配置阈值的关键点视为缺失。

### 双手帧 `HandsFrame`

- 每帧最多包含 `left`、`right`、`unknown` 三个槽位，同一手别只保留一个检测结果。
- 普通控制优先选择明确的右手；没有右手时允许 `unknown` 继续单手控制，避免系统手别偶发不确定导致失控。
- 左手辅助只读取 `left`，`unknown` 永远不能启用辅助模式。

### 运行状态 `AppRunState`

- `idle`：未启动摄像头。
- `requestingCameraPermission`：等待摄像头决定。
- `previewOnly`：摄像头可用，但不具备辅助功能权限或控制未开启。
- `calibrating`：只采集稳定食指位置，不产生鼠标事件。
- `calibratingGaze`：在目标显示器显示九个注视点，只采集眼部样本，不产生鼠标事件。
- `controlling`：可以产生鼠标事件。
- `paused`：保留预览，不产生鼠标事件。
- `recovering(reason)`：Vision 连续失败后保留摄像头并暂停投递，等待连续两个成功帧自动恢复。
- `error`：摄像头或处理链路失败，不产生鼠标事件。

### 手势状态 `GestureState`

- `noHand`、`pointer`、`primaryPinchPending`、`dragging`、`scrolling`、`paused`。
- 任何离开 `dragging` 的路径都必须先产生一次左键释放命令。

### 左手辅助状态 `AssistMode`

- `none`、`precision`、`cursorLock`、`doubleClick`、`scroll`、`drag`。
- 新姿势必须持续至少 0.12 秒且连续出现两帧才切换；左手短暂遮挡 0.20 秒内保留当前模式，超时立即退出并释放辅助拖拽。

### 右手抓窗状态 `WindowGrabPhase`

- `idle`、`openCandidate`、`armed`、`grabbed`、`awaitNeutral`。
- 明确右手，或画面里只有一只未知手时，可以进入候选。左手不能武装抓窗。已经开始的抓取不因手别短暂变成未知而取消。
- 状态只保存在当前引擎会话中，不持久化窗口引用、窗口坐标或抓窗进度；停止后必须回到 `idle`。

### 设置 `AirControlSettings`

- 控制区域：默认 `x=0.10...0.90`、`y=0.10...0.90`。
- 平滑系数：默认 `0.32`，范围 `0.05...1.0`；控制按真实帧间隔计算，数值越大越跟手，数值越小越稳定。
- 最低关键点置信度：默认 `0.35`。
- 捏合距离除以腕部到中指掌指关节的距离后计算；进入阈值默认 `0.28`，退出阈值默认 `0.45`，退出阈值必须更大。
- 拖拽保持时间：默认 `0.35` 秒。
- 握拳暂停时间：默认 `0.70` 秒。
- 丢手安全释放时间：默认 `0.20` 秒。
- 目标显示器 ID：默认当前主显示器。
- 摄像头 ID：默认系统首选摄像头。
- 手势开关：第 0 到第 4 位依次表示移动、左键、拖拽、右键、滚动，均默认开启；握拳暂停属于不可关闭的安全手势。修改开关会先安全停止，用户需要再次明确开启控制。

设置由 Rust 提供默认值并校验，以版本化 JSON 写入 `UserDefaults`。读取失败、数值越界或未来版本不兼容时使用安全默认值，不迁移未知数据。摄像头 ID 和显示器 ID 属于平台设备标识，只由 Swift 保存。

### 视线样本与模型

- `GazeSample` 只包含左右瞳孔在各自眼框内的平均归一化坐标、脸部置信度和睁眼状态，不包含图片或身份数据。
- `GazeProfile` 包含二维仿射模型的六个系数和九点样本的横纵覆盖范围。模型、启用开关使用独立 `UserDefaults` 键保存；旧版本升级后默认关闭且未校准。
- 九个目标依次位于目标显示器归一化坐标 `0.12/0.50/0.88` 的三行三列。单点至少两个有效样本并稳定 0.65 秒；低置信度、闭眼、丢脸和超过稳定半径的抖动会清空当前点进度。
- 模型和显示器边界由 Rust 校验。映射结果始终限制在目标显示器内，并按真实帧间隔平滑。

## 手势决策规则

所有规则使用手掌尺寸归一化后的距离，避免手靠近摄像头时阈值失效。分类优先级为：左手安全暂停、左手辅助拖拽、辅助点击/滚动/锁定、普通拖拽、普通捏合、普通滚动、光标、无手。

1. 食指三点有效且保持伸展时，其指尖先按真实帧间隔经过同一时间常数的低通滤波，小移动和大移动走同一响应，避免慢了再追赶造成跳跃。手刚进入画面时记录指尖锚点，滤波后的位移未超过 0.08 前不移动光标。超过后按校准范围的增益，从当前光标位置相对跟随，不把手指在画面中的绝对位置映射到屏幕。横轴按镜像反转。纵轴使用 Quartz 底左原点：摄像头坐标变大时光标向上；投递 `CGEvent` 时再换成主显示器顶左原点。移出屏幕的那一段位移直接丢掉，下一帧从边缘继续跟，不积压。控制开始时的手掌大小当作当前坐姿距离：手更靠近摄像头时降低增益，更远时提高，比例限制在 0.65 到 1.45。同一实际时长的响应不依赖收到的帧数。视线接管仍立即停在交接光标上，不套用这道起步阈值。
2. 四指伸展或折叠使用各自 `MCP → PIP → Tip` 三点的方向夹角和相对长度判断，不依赖图像纵轴，因此手掌横放或旋转不会改变姿势语义。
3. 每种手势只读取自己需要的关键点。无关手指的点缺失不会让整帧失效；食指伸展证据可在 0.10 秒内短暂沿用，完整握拳仍要求四指证据齐全。
4. 拇指与食指进入捏合阈值的第一帧立即保存当前屏幕光标作为锚点并抑制普通移动；连续两个闭合样本确认捏合。闭合证据短暂缺失不超过 0.08 秒时保持状态，连续两个张开样本才确认松开。
5. 主捏合在 0.35 秒前松开时，只在锚点产生一次左键按下和释放；达到 0.35 秒时只在锚点按下一次左键并进入拖拽，之后才恢复随手移动，松开只释放一次。
6. 拇指与中指捏合复用同一套锚点、双样本确认和 0.08 秒丢点宽限，但不进入拖拽；当前存在主捏合或拖拽时不判断次捏合。
7. 食指和中指伸出、无捏合时进入滚动；相对进入滚动时的指尖中点位移产生滚轮命令，并设置死区防抖。
8. 明确的左手四指折叠形成握拳并稳定 0.70 秒后切换暂停状态；必须等待手重新张开后，下一次握拳才能再次触发。右手或未知手握拳不暂停。
9. 整只手的可靠关键点丢失超过 0.20 秒时清空滤波和手势状态；若正在拖拽，先释放左键。局部缺点只暂停依赖该点的手势判断，不预测光标位置。
10. 暂停、权限丢失、摄像头中断、目标显示器消失、应用退出或紧急停止时，禁止新事件并释放所有按键。
11. 左手张开手掌进入精细稳定模式：右掌位移以相对当前位置的 40% 增益控制光标，不要求右手保持食指姿势；右手捏合仍可点击。
12. 左手仅伸食指进入光标锁定模式：右手移动不改变光标位置，但点击仍落在当前锁定位置。
13. 左手竖拇指进入双击模式：右手主短捏产生一条点击次数为 2 的平台命令，macOS 外壳按系统双击语义投递，Rust 不模拟两次独立点击。
14. 左手 V 手势进入辅助滚动：右掌相对位移转换为滚轮命令，不产生光标移动。
15. 左手伸出三指进入拖拽辅助：进入后在当前光标按下一次左键，右手移动拖拽；退出模式、任一控制手超时丢失、停止或错误均只释放一次。
16. 右手四指全部伸展连续至少两帧且持续 0.12 秒后武装抓窗，并冻结当前光标锚点。只有随后观察到手指数下降，并在 0.65 秒内连续两帧确认四指折叠，才输出一次 `WindowGrabBegin`；确认时用当前拳头掌心重新落定移动基准，但不改变冻结的光标锚点，避免收拢动作造成窗口首帧跳动。画面中直接出现的拳头绝不触发。
17. 抓窗候选及抓住期间抑制普通食指移动、捏合、滚动和点击。抓住后掌心使用与食指光标相同的校准增益和方向输出 `WindowMove`：横轴镜像，纵轴与光标相同，手上移则窗口上移。重新完全张掌连续两帧输出一次 `WindowGrabEnd`，之后等待离开张掌姿势才允许新一轮候选。
18. 收拢超时或中途重新张掌会取消候选。右手丢失超过 0.20 秒、左手辅助进入、左手握拳暂停、用户停止、错误或退出都会先结束活动抓窗。左手暂停优先级始终高于抓窗。
19. 摄像头运行时始终检测画面中最大的一张脸，把轮廓、眉、眼、鼻和嘴画在预览里。这些点不移动光标，也不参与调度台。视线辅助默认关闭；关闭时不输出视线光标。开启后且画面中没有任何手时，可信瞳孔位置可输出粗略光标；闭眼、丢脸、低置信度或无效样本不输出也不点击。
20. 任一手进入画面后视线立即让出控制，并等待丢手安全释放时间后才可恢复。视线移动会在 Rust 引擎中刷新外部光标锚点；右手首次产生有效食指位置时保持该锚点，后续按手部相对位移的 45% 增益精调，短捏点击仍使用精调后的屏幕锚点。
21. 明确的左右手都张开，先稳定 0.10 秒，再在 0.50 秒内一起向上移动至少 0.12 且横向漂移小于 0.10，输出一次 `ShowAppOverview`。之后用现有食指和短捏在调度台里点选。两只手腕距离小于 0.12 时视为重合：按上一帧的手腕位置保持左右归属，不切换辅助、不开始调度，也不把右手拳头当成左手暂停。

## 校准与显示器

校准分两步：用户将食指稳定保持在舒适范围左上角 0.8 秒，再保持在右下角 0.8 秒。宽度小于 0.25、高度小于 0.20、方向颠倒或关键点不稳定均判定失败且不覆盖旧设置。

视线校准与手部活动范围校准相互独立。视线重新校准被取消或九点覆盖不足时保留旧模型；没有旧模型时保持视线辅助关闭。按 Escape 可以取消全屏九点校准。

显示器使用稳定 ID 保存。目标显示器不存在时，立即暂停控制并回退到当前主显示器；用户需再次明确开启控制。跨显示器坐标不依赖屏幕排列方向。

## 权限、安全与隐私

- 摄像头授权前不创建捕获输入；拒绝后显示前往系统设置的说明。
- 辅助功能未授权时允许预览，但 `SystemCursorController` 不投递任何事件，也不移动窗口。
- 不申请麦克风、屏幕录制、输入监控、网络或文件访问权限。
- 视频样本只存在于当前处理帧内；设置中不包含图片或生物特征。
- 主窗口默认不显示摄像头画面，只绘制识别到的关节点。用户可以打开“显示摄像头画面”；关闭后预览层不显示像素，识别点仍在。这个开关不改变摄像头采集，也不能关闭 macOS 的绿色隐私灯。
- 预览是镜像：识别点和可选的摄像头画面使用同一套水平翻转，观看者的右侧对应画面右侧。预览层把画面顶部换成较小的视图坐标，叠加层再翻回来，所以头顶和举手都留在画面上方。打开画面时点落在画面实际显示区域内，而不是被裁切后的另一套坐标。头部轮廓用单独的颜色绘制，不和手部骨架连在一起。
- 视线设置只保存启用开关和数值模型系数，不保存人脸框、眼睛轮廓、瞳孔图片或身份模板；视线辅助复用摄像头和辅助功能，不新增权限。
- 抓窗只通过辅助功能接口定位光标下元素所属的窗口并设置窗口位置，不读取窗口内容、不截图，也不申请屏幕录制权限。光标坐标先从 Quartz 底左原点转换成辅助功能的主屏顶左原点，再命中窗口；命中控件时沿父级找到可移动窗口。光标下最前面、位置可写的窗口就是抓取目标，包括 AirControl 自己的主窗口。只有该窗口位置不可写时，才改看它后面的窗口。忽略鼠标的覆盖层不会成为命中目标。抓住后窗口与光标使用同一位移。
- 全局快捷键、菜单栏、握拳、窗口停用按钮和应用退出都调用同一个安全停止入口。
- 本机开发安装固定使用登录钥匙串中的 `AirControl Local Code Signing` 和应用标识 `com.liuchong.AirControl`。签名指定要求必须同时绑定应用标识与该证书，禁止仅绑定本次构建哈希。
- 本地签名身份、应用标识或严格签名验证任一不满足时禁止安装，不得回退到临时签名。私钥只保存在登录钥匙串，不进入仓库或构建产物。
- 从临时签名首次迁移到固定签名时允许 macOS 要求重新授权一次；如果旧辅助功能行仍绑定临时身份，应移除旧行并重新添加当前 `/Applications/AirControl.app`。同一身份的后续覆盖安装必须保持指定要求一致并继承授权。对外分发和 Apple 公证不属于本地开发签名的能力。

## 失败回退

- 摄像头断开或初始化失败：进入 `error`，安全停止，保留重新选择入口。
- Vision 处理失败：当前帧按“未检测到手”转交 Rust，使丢手安全计时继续生效；连续 5 帧失败时释放按键并进入 `recovering`，但不停止摄像头。恢复期间仍处理帧但不投递鼠标命令，连续两个成功帧后自动回到控制状态；恢复中的失败会重新累计成功帧。
- 摄像头初始化、中断或会话错误：进入 `error` 并停止会话；用户再次开启时必须重新配置所选摄像头并启动新会话，不能只切换界面布尔值。
- Vision 成功但单个已知关节的坐标或置信度无效：Rust C 兼容接口忽略该测量；无关点缺失不影响其他手势，所需点不足时只暂停对应手势，全部可靠点丢失才进入丢手计时。未知关节类型、空指针、非有限时间戳和非法输出缓冲区仍返回调用错误。
- 帧处理积压：只保留最新帧，不排队追赶。
- Rust 处理或鼠标事件创建失败：安全停止，并在主窗口显示具体错误文字。
- 光标下没有窗口、窗口位置不可写、全屏窗口或系统表面拒绝移动：只取消本次平台窗口会话并忽略后续移动，AirControl 继续控制；辅助功能授权丢失仍按真实错误安全停止。
- 设置损坏：恢复默认值并提示已恢复，不让错误配置驱动系统事件。
- 视线样本无效：只冻结视线输出，不影响仍然有效的手势请求；视线模型损坏时视为未校准并保持关闭。

## BDD 验收场景

### 场景 1：权限完整时开启控制

Given 摄像头和辅助功能均已授权，When 用户开启控制并伸出食指，Then 光标按校准区域平滑移动且状态显示“控制中”。

### 场景 2：摄像头权限被拒绝

Given 摄像头权限被拒绝，When 应用启动，Then 不创建捕获会话、不产生鼠标事件，并显示系统设置指引。

### 场景 3：辅助功能权限缺失

Given 摄像头已授权但辅助功能未授权，When 检测到任何手势，Then 预览继续而鼠标命令接收器得到零条命令。

### 场景 4：短捏单击

Given 正在控制且食指与拇指短捏，When 食指在收拢时改变坐标并在拖拽时间前连续两个样本松开，Then 捏合期间不移动光标，只在捏合前锚点产生一组左键按下和释放。

### 场景 5：长捏拖拽

Given 正在控制且持续捏合，When 达到拖拽时间后移动并连续两个样本松开，Then 只在捏合前锚点产生一次左键按下、进入拖拽后产生若干移动并最终释放一次。

### 场景 6：滚动与点击互斥

Given 食指与中指伸出，When 手指中点上下移动，Then 只产生滚轮命令，不产生点击。

### 场景 7：拖拽时信号丢失

Given 左键处于拖拽按下状态，When 手部丢失超过安全时间，Then 立即产生一次左键释放并清空状态。

### 场景 8：暂停和紧急停止

Given 正在控制，When 握拳稳定达到阈值或触发全局快捷键，Then 所有按键被释放，后续姿态不再产生事件。

### 场景 9：校准无效

Given 已有有效校准，When 新校准范围过小或方向颠倒，Then 显示失败并保留旧校准。

### 场景 10：配置损坏

Given `UserDefaults` 中存在无法解码或越界设置，When 应用加载，Then 使用安全默认设置且不崩溃。

### 场景 11：目标显示器消失

Given 正在控制外接显示器，When 外接显示器断开，Then 立即安全停止并选择主显示器，但不自动恢复控制。

### 场景 12：隐私边界

Given 应用完成摄像头处理，When 检查运行路径与产物，Then 不存在视频写盘、网络请求或麦克风采集行为。

### 场景 13：拖拽期间 Vision 连续报错

Given 左键已由长捏进入拖拽按下状态，When Vision 开始报错且从最后有效手部帧起超过丢手安全时间，Then 每个失败帧都按未检测到手转交 Rust，并在第 5 次连续错误触发终止前释放左键。

### 场景 14：跨语言输出缓冲区不足

Given Rust 引擎本次处理会产生鼠标命令，When 平台外壳提供的输出缓冲区容量不足，Then 接口只返回所需容量且不提交本次状态变化；调用方以相同输入和足够缓冲区重试时得到完全相同的命令。

### 场景 15：校准关键点置信度不足

Given Rust 校准器使用当前设置中的最低置信度，When 平台外壳传入低于阈值的食指点，Then Rust 将其视为缺失且不累计稳定保持时间；Swift 不复制该阈值判断。

### 场景 16：平台设备选择持久化

Given 用户选择了当前存在的摄像头和显示器，When 应用重新启动，Then Swift 恢复这两个平台设备标识；已保存设备不存在时分别回退到系统首选摄像头和当前主显示器，并保存新的有效选择。

### 场景 17：单个关节点越界

Given Vision 成功返回手部帧但其中一个与当前手势无关的已知关节点坐标越界，When Swift 经真实 C 兼容接口交给 Rust，Then 接口返回成功、忽略该点、继续输出当前手势命令且不进入应用错误状态；若缺失的是所需点，只暂停该手势判断。

### 场景 18：旋转后的食指指向

Given 手掌相对图像纵轴旋转且只有食指沿自身关节方向伸出，When Rust 处理该帧，Then 输出光标移动命令且不会当成握拳暂停。

### 场景 19：错误详情可见

Given 处理链路出现不可恢复的真实错误，When 应用安全停止并进入 `error`，Then 主窗口显示“发生错误”和具体错误文字。

### 场景 20：帧率变化下平滑一致

Given 同一条食指轨迹分别以 15 帧和 30 帧每秒输入，When 默认平滑设置处理到相同实际时间，Then 两个光标位置的横向差不超过目标屏幕宽度的 2%，且都不会直接跳到目标边缘。

### 场景 21：捏合短暂缺点

Given 主捏合已经得到闭合样本，When 拇指关键点短暂缺失并在 0.08 秒内恢复，Then 捏合继续确认、不提前点击且不移动光标，之后连续两个张开样本只产生一次点击。

### 场景 22：固定签名跨构建保持权限身份

Given 登录钥匙串存在固定本地签名身份，When 两份代码内容不同的 `com.liuchong.AirControl` 应用依次构建、签名和覆盖安装，Then 两份应用的指定要求相同且不只绑定代码哈希；身份缺失或应用标识不符时安装在替换现有应用前失败。

### 场景 23：左手精细稳定且右手任意姿势可移动

Given 左手张开手掌已稳定进入精细模式，When 右手以任意非点击姿势移动手掌，Then 光标按右掌相对位移的 40% 移动；右手捏合仍在稳定位置点击。

### 场景 24：左手锁定光标后点击

Given 左手仅伸食指已稳定，When 右手移动并完成主短捏，Then 光标保持原位且在原位产生一次左键单击。

### 场景 25：左手竖拇指启用真实双击

Given 左手竖拇指已稳定，When 右手完成一次主短捏，Then 跨语言接口输出点击次数为 2 的单条点击命令，macOS 投递系统双击状态。

### 场景 26：左手辅助滚动和拖拽安全退出

Given 左手分别稳定为 V 手势或三指，When 右掌移动，Then 前者只产生滚轮命令，后者只按下一次左键并移动；左手遮挡超过 0.20 秒时拖拽立即释放。

### 场景 27：手别不确定不启用辅助

Given Vision 只能返回未知手别，When 该手做出任一左手辅助姿势，Then 仍可按单手规则控制，但不会进入任何辅助模式。

### 场景 28：停止清除暂停并可重新开启

Given 左手握拳使引擎暂停，When 用户停止后再次开启，Then 新会话不是暂停状态并可立即处理有效手势；右手握拳始终不会暂停。

### 场景 29：Vision 连续失败自动恢复

Given 正在控制，When Vision 连续失败 5 帧，Then 应用释放按键、保留摄像头并显示恢复中；随后连续两个成功帧时自动恢复控制，不要求用户停止再开启。

### 场景 30：真实摄像头错误后重新配置

Given 摄像头会话发生不可恢复错误并停止，When 用户再次开启控制，Then 应用重新配置当前选择的摄像头、启动会话，再进入控制。

### 场景 31：完整过程从任意区域抓窗

Given 明确右手稳定张掌至少 0.12 秒，When 右手在 0.65 秒内收拢并连续两帧握拳，Then Rust 只在张掌前冻结的光标锚点输出一次开始抓窗，并在握拳确认时重置掌心移动基准；保持拳头不动时窗口不因收拢偏移而跳动，随后移动掌心时 macOS 按相同位移移动窗口和光标，不产生点击或鼠标按下。

### 场景 32：孤立拳头和取消过程不抓窗

Given 没有先看到稳定张掌，When 右拳持续出现，Then 不产生窗口、暂停或点击命令；Given 已武装抓窗，When 收拢超时或中途重新张掌，Then 取消候选并要求从新一轮稳定张掌开始。

### 场景 33：抓窗安全释放和左手优先

Given 窗口已被抓住，When 右手重新张掌、丢失超过 0.20 秒、左手辅助进入、左手握拳暂停、用户停止或发生错误，Then 只结束一次抓窗；左手暂停发生时结束命令排在暂停命令之前。

### 场景 34：不可移动窗口软失败

Given 光标下没有可移动窗口或窗口位置属性不可写，When 平台收到开始抓窗命令，Then 不模拟内容点击、不停止 AirControl，并忽略本轮后续窗口移动直到结束。

### 场景 35：抓窗跨语言事务语义

Given Rust 即将输出开始或结束抓窗命令，When C 兼容接口输出缓冲区不足，Then 只报告所需容量且不提交状态；相同输入以足够容量重试时得到同一命令，真实 Swift 静态库夹具得到开始、移动、结束的完整顺序。

### 场景 36：九点视线校准和默认关闭

Given 用户从旧版本升级且没有视线设置，When 应用启动并由用户首次开启视线辅助，Then 默认状态原本为关闭，应用停止控制并依次显示九个目标；九点稳定完成后只保存数值模型并启用视线。

### 场景 37：无效眼部信号冻结

Given 视线辅助正在粗定位，When 用户闭眼、瞳孔缺失、脸部丢失或置信度不足，Then Rust 映射器不输出新位置、不点击且不让应用进入错误状态。

### 场景 38：视线到右手无跳动接管

Given 视线将光标移动到目标附近，When 右手进入并首次伸出食指，Then 第一个有效手部移动保持当前光标，后续手部位移以相对精细增益控制，短捏仍点击精调后的位置。

### 场景 39：取消视线校准保留旧模型

Given 已有有效视线模型，When 用户重新校准后按 Escape，Then 未完成样本不写入，旧模型和此前启用状态保持不变。

### 场景 40：校准完成后恢复原控制意图

Given 九点校准开始前正在控制，When 校准成功且摄像头、辅助功能权限仍有效，Then 应用通过统一摄像头重连路径自动恢复控制；若开始前只是预览，则保持仅预览。

### 场景 41：校准取消或失败不误启动

Given 校准开始时记录了恢复意图，When 用户取消、模型无效、处理失败或完成时权限失效，Then 恢复意图被一次性清空，应用不自动开启控制。

### 场景 42：屏幕辅助光源默认关闭并持久化

Given 用户从旧版本升级，When 应用启动，Then 目标显示器边缘柔光默认关闭；用户开启并调整亮度、冷暖色后重启，三项设置恢复，损坏或越界数据回退安全默认值。

### 场景 43：辅助光源不干扰系统操作

Given 屏幕辅助光源已开启，When 用户点击目标显示器边缘、切换应用或进行九点校准，Then 覆盖层不接收鼠标、不成为主窗口或键盘窗口，校准点与 Escape 取消仍可用。

### 场景 44：辅助光源权限和平台边界

Given 用户开启辅助光源，When 检查权限与处理路径，Then 应用只绘制自身透明窗口，不读取屏幕、不申请屏幕录制权限，也不尝试关闭 macOS 摄像头绿色隐私指示灯；该平台窗口逻辑不进入 Rust。

### 场景 45：辅助光源关闭状态不能被其他流程绕过

Given 辅助光源开关未选中，When 应用启动、进入九点校准、校准后恢复控制、摄像头重连或显示器变化，Then 每条路径都应用当前关闭设置，不创建、显示或重新置前柔光层；只有用户明确打开开关后才允许显示。

## 验证与停止条件

- Rust 核心行为单元测试、跨语言 ABI 契约测试和 `integration_test/` 的关键点序列测试全部通过。
- Xcode 工程可以生成，Debug 应用可以构建。
- 权限与异常路径不会投递越权事件或遗留鼠标按下状态。
- README、应用内帮助、长期规格和 AI-facing 记录一致。
- 真实摄像头与系统授权无法在无用户确认的自动化测试中代替用户决定，使用本机手动验收清单记录其边界。
- 本地签名集成测试必须证明不同构建的指定要求相同、缺少身份和错误应用标识都会安全失败；连续覆盖安装后的系统授权状态由本机端到端验收补充。
