# AirControl 验证与手动验收

## 自动验证

在仓库根目录运行：

```bash
./scripts/verify.sh
```

也可以分开运行：

```bash
cargo fmt --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
xcodegen generate
xcodebuild build-for-testing -project AirControl.xcodeproj -scheme AirControl \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/DerivedData \
  CODE_SIGNING_ALLOWED=NO
xcodebuild test -project AirControl.xcodeproj -scheme AirControl \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/DerivedData \
  CODE_SIGNING_ALLOWED=NO
```

自动测试不会投递真实鼠标事件。Rust 测试直接验证手势状态机；Swift 集成测试通过真实静态库和 C 兼容接口验证平台适配器，但只检查抽象命令。

## 本地签名与安装验证

以下命令会访问登录钥匙串中的 `AirControl Local Code Signing`，应在普通用户登录的图形会话中运行：

```bash
make signing-check
make signing-test
make install-local
```

`make signing-test` 会构建两份内容不同的最小应用，分别签名后比较指定要求，确保身份同时绑定 `com.liuchong.AirControl` 和同一证书，而不是绑定每次变化的代码哈希。它还验证缺失身份和错误应用标识都会失败。

`make install-local` 会先构建、固定签名并严格验证，再停止现有 AirControl、把旧应用移动到可恢复的临时目录、安装新版本并重新启动。任何步骤失败时会恢复旧应用；签名身份缺失时不会改用临时签名。

## 真实权限与硬件验收

以下项目依赖 macOS 的真实授权窗口、摄像头和显示器热插拔，不适合由无人值守测试代替用户决定：

1. 首次启动拒绝摄像头权限，确认应用不出现画面、不移动光标，并显示系统设置指引。
2. 只授予摄像头、不授予辅助功能权限，确认预览继续，但任何手势都不会控制电脑。
3. 两项权限都授予后开启控制，确认食指移动连续、短捏左键、长捏拖拽、拇指中指右键和双指滚动符合应用内帮助；用不同速度移动食指，确认慢移稳定且快移能跟手。将手掌横放并保持食指伸出，确认仍能移动而不会误触发握拳暂停。
4. 拖拽过程中把手移出画面并保持超过 0.2 秒，确认左键被释放。
5. 控制过程中按 `Control + Option + Command + A`，确认立即停止且不遗留鼠标按下状态。
6. 控制过程中断开正在使用的摄像头，确认进入错误状态并停止控制。
7. 以外接显示器为目标开启控制，然后断开该显示器，确认立即停止、回退主显示器，并且不会自动恢复控制。
8. 拖拽过程中退出应用，确认退出前释放左键。
9. 检查“系统设置 → 隐私与安全性”，确认应用只请求摄像头和辅助功能，没有麦克风、屏幕录制或输入监控权限。
10. 选择非默认摄像头和外接显示器后退出并重新启动，确认选择被恢复；断开已保存设备后重启，确认分别回退到系统首选摄像头和主显示器。
11. 将手移动到画面边缘再移回，确认应用不会因单个关节点短暂越界而进入“发生错误”；若出现其他真实错误，确认主窗口显示具体原因。
12. 把光标停在一个小按钮上，再把食指向拇指收拢完成短捏，确认捏合期间光标不被带走且点击落在原按钮；重复短捏，确认没有漏点或一次捏合触发多次点击。
13. 持续捏合超过 0.35 秒，确认左键在原位置按下，之后移动手才开始拖拽；让拇指在画面中短暂被食指遮住后恢复，确认拖拽或点击不会立即中断。
14. 首次从临时签名迁移时，若辅助功能开关已开启但应用仍显示“需要授权”，移除旧 AirControl 行并通过“添加”选择当前 `/Applications/AirControl.app`；确认应用重启后显示“已授权”。随后再次运行 `make install-local`，确认指定要求相同，重启后摄像头和辅助功能仍显示“已授权”，无需再次修改系统设置。
15. 左手张开手掌并稳定片刻，右手不用保持食指姿势，缓慢移动手掌；确认光标以较低增益精细移动，右手短捏仍能准确单击。
16. 左手仅伸食指，移动右手并短捏；确认光标位置锁定但单击仍生效。
17. 左手竖拇指，右手短捏；确认目标收到一次系统双击。左手做 V 手势并上下移动右掌，确认只滚动、不移动光标。
18. 左手伸三指，移动右手并短暂遮住左手；确认开始拖拽、0.20 秒内短暂遮挡不误松开，持续遮挡或退出姿势后只释放一次左键。
19. 用左手握拳稳定 0.70 秒，确认暂停或恢复；单独右手握拳，确认不会暂停。
20. 控制期间短暂遮挡摄像头或制造连续识别失败，确认界面进入“恢复中”、摄像头预览保持；姿态恢复连续两帧后自动继续。若摄像头被系统断开，重新连接并再次开启，确认应用重建会话后恢复。
21. 检查 Dock/Finder 中的应用图标、菜单栏单色图标与 README 品牌图；确认小尺寸仍能辨认箭头 A 和双翼，暂停与恢复状态有独立徽标。
22. 把光标放在普通应用窗口内容区的任意位置，右手稳定张掌约 0.12 秒，再在 0.65 秒内自然收拢并握拳；确认窗口被抓住，移动右手掌心时窗口与光标同步移动，重新张掌连续片刻后释放。重复时不要求对准标题栏。
23. 未先张掌时直接把右拳放进画面并保持，确认窗口不移动、应用不暂停且不会点击；再尝试张掌后收拢到一半重新张开、或慢于 0.65 秒才握拳，确认都不抓窗。
24. 抓窗期间把右手移出画面超过 0.20 秒，再恢复；确认旧窗口不再跟随。抓窗期间让左手进入任一辅助模式或握拳暂停，确认先释放窗口，再执行左手行为。
25. 在全屏窗口、桌面、Dock 或不可移动的系统表面尝试同一过程，确认 AirControl 保持运行且不会在内容上模拟点击。此项必须真实调用 macOS 辅助功能接口，自动测试只能覆盖位移计算和软失败状态，不能代替系统窗口策略验收。
26. 保持“视线辅助”关闭，观察摄像头和手势性能与旧版本一致；开启后确认目标显示器出现九个圆点，依次注视并保持到进度完成。中途按 Escape，确认取消且没有启用未完成模型。
27. 完成九点校准、开启控制并把双手移出画面，依次看向屏幕中央、四角附近的大按钮，确认光标粗略到达对应区域且不会越出目标显示器。普通摄像头只验收粗定位，不要求像素级命中。
28. 视线移动后把右手放回画面并伸出食指，确认光标第一帧不跳回旧手部绝对位置，随后可小范围精调并用短捏点击。捏合、拖拽、滚动、左手辅助和抓窗期间确认视线不会争抢光标。
29. 视线控制时自然眨眼、闭眼一秒、转头离开画面、戴眼镜并改变室内亮度，确认无可靠眼部信号时光标冻结且绝不点击；恢复清晰视线后可继续粗定位。
30. 退出并重新启动应用，确认视线开关和校准模型恢复；设置中只出现数值模型。切换目标显示器后重新校准，确认新显示器全屏覆盖层和坐标正确。
31. 先开启控制，再重新进行九点视线校准；完成第九点后不点击任何按钮，确认界面先短暂显示摄像头重连、随后自动回到“控制中”且手势/视线可继续控制。分别从仅预览开始校准、按 Escape 取消和制造无效校准，确认都不会误启动控制。
32. 保持“屏幕辅助光源”关闭，依次重启应用、开始九点校准并完成控制恢复，确认全过程都没有柔光；再打开开关并调整亮度和冷暖色，确认目标显示器边缘实时变化。点击被柔光覆盖的边缘内容、切换应用和按 Escape 取消校准，确认覆盖层不抢鼠标或键盘。重启后确认设置恢复，关闭后柔光立即消失。摄像头绿色隐私灯应继续由 macOS 正常显示。
33. 首次启动和重启后，主窗口只显示识别点、不显示摄像头画面。打开“显示摄像头画面”后能看到镜像预览，关掉后画面立即消失且识别点仍在。绿色隐私灯在两种状态下都保持亮起。

## 隐私静态检查

应用生产代码不应出现网络客户端、音频捕获或视频写盘路径。可用以下检查快速发现新增风险，再人工核对命中内容：

```bash
rg -n 'URLSession|NWConnection|AVCaptureAudioDataOutput|AVAssetWriter|FileHandle|write\(to:|Data\(contentsOf' AirControl crates
```

测试读取 JSON fixture 的 `Data(contentsOf:)` 属于测试资源读取，不是摄像头帧写盘或联网。
